# 三建议卡片：试点格式与验证

当前范围：只有主动使用 v1 标记、结构完整的助手消息显示为三建议卡片。
普通消息、用户粘贴的格式示例、无效或未完成格式继续走 Markdown。
不是通用 HTML 执行能力，也不自动把任意三点列表改成卡片。

## 内容契约

整条助手消息由以下 Markdown 组成，不包代码围栏，不在标记外增加文字：

~~~markdown
<!-- cindy:advice:v1 -->
## 回答标题

简短开场。

### 第一条建议标题
第一条建议的解释。

> **可以先做**
> 一个具体行动。

### 第二条建议标题
第二条建议的解释。

> **可以先做**
> 一个具体行动。

### 第三条建议标题
第三条建议的解释。

> **可以先做**
> 一个具体行动。

---
必须保留的限制、依据边界或不确定性说明。
<!-- /cindy:advice -->
~~~

恰好三个三级标题；二级标题、开场、每条解释和行动、结尾说明均非空。
行动标签由内容提供，可用相应语言。多段行动每行继续使用引用前缀。
首版字段为纯文本，不在其中生成链接、图片、内联 Markdown 或 HTML。
总长最多 16000 UTF-16 单元；标题 160、开场与结尾各 2000、解释与行动各 3000、行动标签 80。
不支持的版本、嵌套标记、围栏或无效结构均回退原有 Markdown，不丢原消息。

生成时通过本轮用户指令明确提供格式；本试点不修改系统提示词，不承诺模型在任意问题中自动选用。
可用下面的指令验证实际生成：

> 请用本文的三建议卡片 v1 格式回答。主题是完成项目、区分观察与解释、在不确定中保持稳定。
> 每条保留解释和一个具体行动，保留结尾的不确定性说明。
> 只输出完整的带标记 Markdown，不加代码围栏或格式说明。

## 实现与存储

- 识别：maker-shared 的 adviceAnswer.ts，桌面与手机共用。
- 展示：两个客户端各自的 AdviceAnswerCards 原生组件；文本转义，不执行脚本或主机操作。
- 阅读结构：单个容器中的三条紧凑行，以编号、标题与细分隔线定位；行动标签显示为小胶囊、每条具体行动默认完整显示，解释通过该行箭头独立展开，展开后以灰字加左侧边线与缩进区别于行动。标题、开场和结尾限定说明始终显示，不截断正文。
- 展开仅为本地视图状态，不写入消息正文或数据库；重新挂载、重载后恢复紧凑概览，保存的解释仍可再次展开。两端行为一致，复制与模型上下文仍使用完整消息。
- 流式期间沿用 Markdown，消息不再流式且标记完整后展示卡片；这不是对整轮成功状态的额外判断。
- 使用已有消息正文、稳定 clientId、assistantPhase 和 turnCompleted 保存和恢复。
- 无新表、migration、IPC、跨端字段、文件附件、预览 URL 或独立卡片缓存。
- 旧客户端仍显示可读 Markdown；升级后的读取端从同一正文重建卡片。
- 标准标题使交付内容沿用现有工作过程折叠保护；复制、分享和追问沿用原消息链路。
- 现有插件出口卡片优先级不变，不修改插件基座或权限。
- SSH 与设备互联沿用现有正文通道，显示不需要访问工作目录。

## 验证与阶段出口

自动验证应覆盖：分段生成与完整快照不重复、无效格式回退、流式未完成不显示卡片、
真实 createMessage/SQLite 写入后关闭连接并重新读取、两端从保存正文重建同样内容、
限定说明不丢失、内容不能注入可执行 HTML、原有消息与折叠回归。

界面验收必须在带本次改动的隔离开发实例中进行，不直接改正式 profile：

1. 用上述指令生成一条真实助手回复，核对三建议和文字对应。
2. 追问一次，确认旧卡片仍可见、不被折入工作过程。
3. 切换到其他任务再返回，核对内容和稳定消息身份。
4. 重载窗口后核对同一条消息，再重启隔离实例核对数据库恢复。
5. 检查 Light/Dark 和窄窗；手机通过更新后的客户端连接测试主机，再做历史恢复。
6. 中断生成、删去结束标记或使用不支持的版本，应有可读 Markdown，不出现损坏卡片。

测试中的模拟事件、临时数据库重开或组件重挂载不能称为完成上述实机验收。
本轮出口是生成、保存与重载链路通过，且阅读收益仍然成立；未通过时继续修这一条链路，
不扩大到关系图、塔罗或任意 JavaScript。
