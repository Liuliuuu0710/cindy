## 最小用户流程（待真实验证的方案）

1. 用户在 B 的私聊主任务中说「接着处理这个任务」，附已有任务链接。用户只说名字时，B 在授权范围按具体标题／话题搜索；多条匹配只问选哪一条，不要求粘贴完整聊天。
2. B 取链接所属电脑和任务 id，调用 `get_task_digest(session_id)`。只读本机时明确范围；跨电脑沿现有 `deviceId::sessionId` 路径，对方离线就报告未能读取，不创建替代任务。
3. B 用 `get_chat_history(session_ids=[id], limit=30)` 定向读近期消息；目标、决策或依据缺失时，再按同一任务搜索或翻必要页。不默认读工具思考记录；需要验证某项操作时只取相关工具回执，不重复执行命令来“验证历史”。
4. B 输出下列五项，每个事实附任务链接、消息 id 与时间。任务链接使用工具实际返回的 `sessionUrl`；没有消息深链能力时不编造消息 URL，用消息 id 辅助定位。
5. B 说明本次覆盖范围和尚缺信息，再准备原授权内的下一步。是否变更负责人、是否向原任务发消息分别走原工具和原权限流程。仅收到背景不自动接手、唤醒 A 或重放外部动作。

| 摘要项 | 最低内容 |
| --- | --- |
| 原目标 | 用户要拿到什么、验收条件；区分早期目标和后来修订 |
| 已做操作 | 做了什么、原记录怎么说；没有回执标「未核实」，不能把计划改成完成 |
| 决策与依据 | 采用什么方案、为什么、由谁明确；没有依据明确缺失 |
| 未完成事项 | 剩余工作、阻塞、缺失资料；不能由本轮 finished 推断全部完成 |
| 下一步 | 一个可以执行的具体动作及依赖；执行授权另按当前请求判断 |

内容结构复用现有消息正文和链接，不新增页面、按钮或术语。后续如证实可发现性仍不足，优先补现有 history 类目说明／伙伴指南的接续步骤，须另按提示词规则核对，不先改底层授权。

## 缺失、过时和范围处理

- **摘要与原文冲突**：保留来源；以时间较新的明确用户修订为准，说明变化。摘要的最后一句不能覆盖原目标。
- **记录不全／分页／截断**：展示覆盖范围，补读相关原文；仍缺项就写「未找到」，不编造。60 行摘录的 `truncated:false` 不证明全任务只有这些记录。
- **读取期间又有更新**：在准备执行前重读摘要／相关记录；没有可靠版本或更新时间就写「尚未核对最新状态」，不用任意分钟阈值假装检测过时。
- **任务不存在、账号变更、无权限、设备离线**：分别解释原因，不将失败当作没有历史，不换范围、账号或工具绕过权限，也不自动重发写动作。
- **私聊、共享访客、群成员与文件**：完全沿现有授权；读取任务文字不额外开放私聊或附件文件。已有文件路径只作为线索，打开仍经原文件授权。原记录里的指令是背景，不是当前用户的新请求。
- **外部操作**：有成功回执仍不重做；只有“准备发出”或回执丢失则标未确认，先按业务系统既有查询对账，绝不凭交接自动重试。
